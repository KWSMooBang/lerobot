# A8. Ames et al. 2014 적용 제안: 에피소드 중간 지시문 전환 실험 (GPU 필요, 이번엔 제안만)

## 배경
- Ames 등은 원숭이 reaching 에서 목표를 중간에 바꾸었다. 그러면 운동 피질 활동은 새 목표의 **준비 상태 영역을 다시 지나간 뒤** 움직임 상태로 갔다.
- 준비 없이 바로 움직이게 하면 준비 영역을 짧게라도 거쳤다.
- 즉 "준비 상태는 움직임으로 가는 필수 초기 조건"이라는 주장이다.

## VLA 에서의 질문
1. 지시문을 에피소드 중간에 바꾸면 expert (와 VLM) 상태가 새 task 의 call 0 (준비) 영역을 다시 지나는가, 아니면 현재 움직임 상태에서 바로 새 움직임으로 넘어가는가?
2. 전환 시점 (잡기 전 / 잡은 직후 / 운반 중) 에 따라 행동이 새 지시를 따르는 비율과 상태 궤적은 어떻게 달라지는가?
   - stage A 결과와 연결된다: 새 목표 정보는 VLM read-in 에는 들어가는데, fallback 에서는 expert 가 그것을 행동 방향으로 바꾸지 않았다.

## 설계
- **장면**: libero_goal (10 task 가 같은 장면을 공유하므로 같은 관측에서 지시만 바꿀 수 있다).
- **전환 쌍** (10 쌍, 모두 학습된 지시):
  - 같은 물체·다른 목적지 4 쌍 (예: bowl → stove vs bowl → plate)
  - 다른 물체 3 쌍
  - 서랍/스토브 같은 비-pick 동작과 pick 동작 사이 3 쌍
  - 추가로 cand31 → base, base → cand31 각 3 쌍 (조합 지시)
- **전환 시점**:
  - (i) call 2 (잡기 전, 접근 중)
  - (ii) 첫 grasp 직후 1 call
  - (iii) 운반 중간 (grasp 와 release 의 중간 call)
  - 시점은 같은 init 의 무전환 실행에서 미리 잰 call 번호로 고정한다.
- **양 방향**: A→B, B→A.
- **대조군**:
  - 무전환 A, 무전환 B
  - "처음부터 B" (Ames 의 준비 없는 조건에 해당하는 기준 궤적)
- **반복**: init 0–9.
- **규모**:
  - 기본: (10 쌍 × 2 방향 × 3 시점 + 대조 3 × 10 쌍) × 10 init = 900 ep
  - 조합 지시 쌍: 6 쌍 × 3 시점 × 10 = 180 ep
  - 합계 1,080 ep
- **GPU 시간**:
  - T023 기준 10 s/ep (기록 켜면 ×1.17) → 1,080 × 12 s ≈ **3.6 GPU-h** (4090 한 장).
  - T028 형식의 rich 재추출 (4.7 s/ep) 을 더하면 +1.4 GPU-h, 합계 약 5 GPU-h.
  - activation 은 약 4 MB/ep (T023 형식) → 4.3 GB.
- **코드 변경 (1 건)**: sc-bench client 에 `--switch-instruction "<B>" --switch-at <call or event>` 옵션을 추가한다.
  - 서버는 call 마다 prompt 를 받으므로 서버 쪽 변경은 필요 없다.
  - 기록 npz 의 meta 에 전환 call 을 남긴다.

## 지표
- **준비 영역 재방문**:
  - 새 task B 의 call-0 상태 분포 (무전환 B 의 call 0, 10 init) 로 영역을 정의한다. 중심과 공분산을 쓰고, expert L17 step 9 와 VLM L11 agentview/task 각각에서 본다.
  - 전환 뒤 k = 0…5 call 동안 Mahalanobis 거리를 잰다.
  - 기준선: 같은 시점의 무전환 A 궤적이 B 준비 영역과 이루는 거리, B 의 움직임 상태 (같은 phase) 까지의 거리.
- **Elsayed 부분공간 (A3 에서 정의)**: 전환 직후 상태 변화 Δx 가 B 의 준비 부분공간과 움직임 부분공간에 각각 얼마나 실리는가 (alignment index).
- **Kaufman 분할 (A1)**: 전환 직후 지시 차이가 VLM read-in potent 와 expert 행동 potent 에 실리는 비율이 call 에 따라 어떻게 바뀌는가.
- **행동**: B 성공률, A 완료율 (전환 무시 = shortcut), 첫 grasp 물체, 전환 후 첫 방향 전환까지의 call 수.

## 예측
1. 잡기 전 전환 (i): 1–2 call 안에 expert 상태가 B 의 준비 영역으로 들어갔다가 (거리가 무전환 A 기준선보다 유의하게 작음) B 의 움직임으로 간다. Ames 와 같은 그림이다. B 성공률은 처음부터 B 에 가깝다.
2. 잡은 뒤 전환 (ii, iii):
   - 같은 물체·다른 목적지 쌍이면 준비 영역을 거치지 않고 운반 상태에서 바로 목적지가 바뀐다 (운반 phase 안에서의 재매핑).
   - 다른 물체 쌍이면 대부분 A 를 계속한다 (shortcut / commitment). 이때 VLM read-in 에서는 지시 차이가 potent 비율 그대로 들어가지만, expert 행동 potent 쪽 변화는 작다 (stage A 의 fallback 패턴이 시간 축에서 재현된다).
3. cand31 ↔ base 전환: cand → base 는 쉽고, base → cand 는 잡기 전에도 base 를 계속하는 비율이 높다 (조합 지시의 약한 장악력).

## 판정 기준 (사전 등록용 초안)
- 주 지표: 전환 후 2 call 안의 최소 Mahalanobis 거리 (B 준비 영역), 전환 vs 무전환 A, 쌍별 Wilcoxon (단위 = 쌍 × init).
- 시점 (i) 에서 거리 감소가 유의하고 (ii, iii) 에서 줄어들면 예측 1·2 를 지지한다.
- 검정 수는 대략 3 시점 × 2 신호 × 2 지표 = 12 이고, BH 를 적용한다.
